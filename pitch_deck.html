Agent Design

04Bounded agent with explicit states

Not a black-box LLM call — a deterministic, testable agent with clear states, step tracking, and honest outcomes.
# Agent state machine — 7 explicit states class AgentState: IDLE = "idle" VALIDATING = "validating" LOADING = "loading" ANALYZING = "analyzing" HYPOTHESIZING="hypothesizing" EVALUATING = "evaluating" REPORTING = "reporting" COMPLETED = "completed" PARTIAL = "partial" BLOCKED = "blocked" FAILED = "failed" # Every hypothesis carries evidence hypothesis = { "confidence": 0.88, # computed, not invented "supporting_evidence": [...], # ✓ cited "contradictory_evidence": [...],# ✗ cited "suspected_commit": "a1b2c3d", "fix_recommendation": "..." }
✅

Deterministic rules

Default demo uses rule-based logic. LLM is an optional adapter, never replaces validation.

🛑

Step limits

Bounded execution with MAX_STEPS. Agent cannot loop indefinitely.

🔍

Honest outcomes

Four final states: completed, partial, blocked, failed. Never fabricates results.

🧪

Testable

21 agent-specific tests. Every state transition and edge case covered.

Detection Engine

06Explainable, not magical

Every anomaly has a documented basis. Confidence is computed from change magnitude + evidence, not invented.
# How confidence works def _confidence_from_change(abs_pct_change): if abs_pct_change > 100: return 0.8 # critical elif abs_pct_change > 50: return 0.6 # high elif abs_pct_change > 20: return 0.4 # medium elif abs_pct_change > 10: return 0.25 # low return 0.1 # negligible # Then adjusted by evidence: # +0.20 if matching commit found # +0.10 if log evidence supports # −0.10 × N for each contradictory finding
📐

Severity classification

critical >100% • high >50% • medium >25% • low >10%

0️⃣

Zero-baseline safe

Handles error_rate=0% → 5% without division by zero. Explicit edge case coverage.

📊

Robust statistics

Median + IQR for noisy data. Handles None, NaN, and small sample sizes gracefully.

🚫

No false positives

Normal runs within ±10% pass cleanly. 11 anomaly tests confirm sensitivity and specificity.

Log Intelligence

07Beyond grep — pattern grouping and correlation

Request IDs, timestamps, hex hashes are normalized into patterns. Error bursts are detected and correlated with metric anomalies.

Built-In Guardrails

09Security by design, not as an afterthought

Every input boundary is validated. The agent reads data, never executes it. Deterministic output is never labeled as AI-generated.
🛡

Input validation

1MB payload limit. Dangerous key rejection (__proto__, eval, exec). JSON structure enforcement.

🔗

URL sanitization

Blocks javascript:, data:, and other unsafe URL schemes. Whitelist-based host checking for outbound requests.

📂

Path traversal prevention

Normalized path resolution. Rejects ../ sequences. Static files served from project root only.

🔒

No secrets in code

No API keys, no credentials, no tokens in source. .env and secrets in .gitignore.

📖

Read-only tools

Agent only reads fixture files. No shell execution, no filesystem write access, no code evaluation.

🎯

Prompt injection resistant

Deterministic output never labeled as LLM-generated. Log data treated as untrusted. 2 dedicated injection tests.
